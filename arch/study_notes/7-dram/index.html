本讲主线

Cache Miss 后，请求怎样进入主存？DRAM 先打开一行，再从行缓冲中读写数据；内存控制器负责把请求变成符合时序约束的命令。后半部分围绕三个目标展开：增加容量、利用组织与调度提高性能、提高接口传输速率。

本文依据《7-DRAM-2025-1》整理。课件第 1—8 页是 Cache 优化的复习，相关内容见上一篇笔记；这里从 DRAM 正文开始。各节保留课堂补充空间，页码按课件实际页面计。

一、DRAM怎样保存和读出数据
#

课件：第 9—21 页。

DRAM 通常用于主存，一个典型存储单元由 **1 个晶体管和 1 个电容（1T1C）**组成，保存 1 bit。字线 WL 控制访问晶体管，位线 BL 用于读写，电容中的电荷状态表示数据。

为了在有限芯片面积内提供足够电容，实际结构可以沿垂直方向展开。课件以 **Trench Cell（沟槽电容单元）**为例，重点是增加有效电容面积，同时减小平面占地，而非要求记住具体工艺结构。

多个单元构成二维阵列 MAT。行地址选中字线，列地址选择要输出的数据；Sense Amplifier（感应放大器）检测并放大微小电压差，其相关电路也承担 **Row Buffer（行缓冲）**的作用。

（DRAM会先用row decoder选中一行，读到Row Buffer，再从Buffer中选择列读出数据。）

问题 原因与处理
破坏性读取 单元与位线共享电荷，读取会扰动原有电荷状态；感应放大器判断并放大后，把数据恢复到单元
漏电 即使不访问，电荷也会逐渐流失；必须周期性刷新，课件以常见的约 64 ms 刷新窗口说明

读取后的恢复和周期性刷新要分清。 前者修复本次读取引起的扰动，后者保证长期未访问的数据也不会因漏电丢失。刷新周期取决于器件与工作条件，不能把 64 ms 理解为所有 DRAM 永远相同的固定参数。

课件说“读完数据消失”，强调的是电荷状态受到破坏；数据已经被感应放大器识别，随后恢复，并不是一次正常读取会让软件丢失数据。

二、从存储单元到内存通道
#

课件：第 16、22—27 页。

DRAM 不是一整块巨大的阵列，而是逐层组织起来的：

Cell → MAT → Bank → Chip
                   多个 Chip 协同组成 Rank
                   一个 Channel 可以连接多个 Rank / DIMM
层次 含义 理解重点
Cell 存储单元 通常保存 1 bit
MAT 由单元构成的局部阵列 使用行列译码和局部感应放大电路
Bank 由多个 MAT 等结构组成的操作单元 不同 Bank 可以保持各自的行状态，部分操作可并行
Chip DRAM 芯片 集成多个 Bank 和外围接口，每次提供一定数据位宽
Rank 一组同时响应选择、协同提供数据位宽的芯片 多个芯片并行“拼宽”数据接口
DIMM 承载芯片的内存模块，也就是常说的内存条 一条 DIMM 可以有一个或多个 Rank
Channel 内存控制器连接内存的接口通路 通道内共享命令与数据等资源，独立通道可增加并行传输能力

bank能独立服务；chip需要多个chip同时协作服务

Rank 和 DIMM 不是同一个概念。 例如，在不计 ECC 的 64-bit 接口示例中，8 颗 x8 芯片可以组成一个 Rank：每颗贡献 8 bit，合起来提供 64 bit。这里的 x8 表示接口位宽，不是容量为 8 字节。

为什么要分 MAT、Bank？大阵列便于摊薄外围电路面积，但长字线、长位线增加延迟与能耗；拆成较小阵列有利于速度和功耗，却需要更多外围电路。Bank 还为后续并行调度提供了基础。

联系 Cache 中的 Bank

两者都通过分区提供并行机会，但 DRAM Bank 有行激活、行缓冲与预充电状态，不能直接套用 Cache 的 Set / Way 关系。

三、一次DRAM访问：命令、行缓冲与时序
#

课件：第 28—42、63—64 页。

访问 DRAM 需要先准备行，再选择列。 在课件的 Bank 级简化模型中，打开的一行保留在 Row Buffer 中，后续可以从中选择不同列进行访问。

操作 命令 在做什么
打开行 ACT / Activate 选中一行，感应放大其数据，并恢复单元电荷
读写列 READ / WRITE 从已打开行的指定列读出或写入数据，通常以 Burst 传输
关闭并准备 PRE / Precharge 关闭当前行，让位线回到适合下一次激活的状态 
Bank 已关闭：ACT 打开目标行 → READ / WRITE
目标行已打开：直接 READ / WRITE
另一行已打开：PRE 关闭旧行 → ACT 打开新行 → READ / WRITE

对应三种情况：Row Hit 是目标行已经打开；Row Closed / Empty 是当前没有打开行；Row Conflict 是同一 Bank 打开了另一行。第三种通常需要额外的预充电与激活等待。

这里的“页”和“冲突”

DRAM Row 也叫 DRAM Page，大小不必等于 OS 的虚拟内存页。Row-buffer Miss 也不等于 Cache Miss；其中“另一行已经打开”的冲突情况，需要先关闭旧行。

命令之间必须间隔足够时间，不能连续随意发出：

tRCD和tRAS的目的是减少DRAM和内存控制器之间的访问，是一个协商的值，在启动的时候会测试出一个能够正常通信的值。

参数 直观含义
tRCD ACT 到允许发出 READ / WRITE 的最小间隔（从ACT到数据到达Row Buffer的最短时间）
tCL / CAS Latency READ 命令到读数据开始输出的延迟，课件写作 tCAS
tRAS 行激活后，允许预充电之前必须保持的最短时间
tRP 预充电后，到下一次激活所需的时间（不包含把数据写回到DRAM cell的时间）
tRC 同一 Bank 两次激活之间的行周期，基本关系为 tRC = tRAS + tRP
tCCD 列访问命令之间的最小间隔
tBURST 一次 Burst 占用数据总线的时长（传输）

做简单读时序题时，可先分辨 Row Hit、Closed、Conflict，再考虑分别需要哪些等待。例如冲突可能需要 tRP、tRCD、tCL，再加数据传输时间。实际还受前序命令、总线占用等约束，不能把所有请求都套成同一个固定延迟。

接口 相比前一步的主要变化
异步 DRAM 由 RAS、CAS 等选通信号指示行列地址的有效时机
Fast Page Mode 保持同一行，连续发送不同列地址，利用行局部性
EDO 增加输出保持能力，让下一列地址的接收与前一数据输出重叠
Burst EDO 利用连续列访问，由内部计数等机制减少重复列地址发送
SDRAM 引入时钟，按规定时钟边沿接收命令、管理时序
DDR SDRAM 数据在时钟上升沿和下降沿均可传输，提高接口数据率

四、目标一：增加容量及模块扩展
#

课件：第 43—51、102 页。

课件先讨论两种扩容量思路：堆叠芯片或板级结构，以及一个 Channel 连接多个 DIMM。它们增加容量，但未必增加共享数据总线的峰值带宽。

更多模块接入后，电路负载与布线问题会变突出。课件举例：一个通道有 3 条 DIMM，每条 8 颗芯片，地址 / 命令信号可能要驱动 24 颗芯片；过大的负载会影响信号质量。

方案 核心做法 代价与关注点
Memory Stacking 通过 Die 堆叠等方式增加密度 封装、散热与互连
RDIMM 对地址 / 命令信号进行寄存和重新驱动 降低控制器看到的负载，可能增加延迟
FB-DIMM 使用 AMB（Advanced Memory Buffer）缓冲并转接通信 课件强调 AMB 的功耗、温度与散热成本
LRDIMM 对数据等信号也进行缓冲，降低电气负载 与 FB-DIMM 的接口及缓冲组织不同

这里 Buffer 的作用是缓冲、重新驱动信号，帮助连接更多器件，与 Cache 保留常用数据的用途不同。课件把 FB-DIMM、LRDIMM 放在同一条思路中比较，理解重点是容量扩展背后的电气负载问题。

五、目标二：内存控制器与资源感知调度
#

课件：第 52—73 页。

内存控制器（Memory Controller，MC）把读写请求转换成 DRAM 能执行的命令，并安排发送时间。 它既要遵守时序，又希望减少等待、提高吞吐量，并兼顾不同请求源。

课件按六步逐渐补全控制器：

接收请求 → 缓冲与仲裁 → 映射到 Rank / Bank / Row / Column
         → 命令队列与调度 → 电气接口发送 → 按时序访问 DRAM
  • 接收请求：来自CPU、DMA、I/O等，可能是读或写，可能有不同优先级。
  • 缓冲与仲裁：请求可能来自不同源，控制器需要缓冲。
  • 交给Rank和Bank利用并行度来处理
  • Bank内重新调度：根据优先级、局部性等因素，重新安排请求的发送时间。

这里的地址映射使用的是物理地址：决定数据位于哪个通道、Rank、Bank、行、列。它与 MMU 将 VA 翻译成 PA 是两个不同步骤。

早期控制器可以位于 CPU 外部的北桥；集成到 CPU 后，可以减少外部链路带来的延迟，但处理器实现也与所支持的内存接口联系得更紧密。

调度有两个主要机会：利用行缓冲局部性，以及利用 Rank/Bank 并行性。

  • Open-page policy：访问后暂时保持行打开，希望后续请求命中同一行；适合行局部性较好的访问流。一旦miss（bank conflict），延迟会长因为多一次precharge。
  • Closed-page policy：访问完成后关闭行并预充电；后续访问另一行时可减少现场关闭旧行的等待，但同一行再次访问也要重新激活。
  • Bank-level Parallelism：某个 Bank 等待激活或预充电时，可安排另一个 Bank 的操作；但同一共享数据接口不能让所有 Bank 同时各自传输一份数据。

地址映射影响“局部性”与“并行性”的分配。 地址中变化较慢的位用于 Row，有利于连续访问保持同行；变化较快的位用于 Bank，有利于把请求分散开。具体位布局不是统一固定的，需结合访问模式与硬件实现。

课件继续介绍了几种映射研究思路，先保留框架：

方法 要解决的问题
访问图与最优映射 根据访问先后关系分组，寻找有利于局部性的分配；课件给出的优化问题具有较高计算复杂度
BIM（Binary Invertible Matrix） 用可逆的二进制矩阵变换构造一一映射，可表示位重排及异或组合等形式
熵驱动映射 用位的变化特征指导字段选择：低熵位倾向用于 Row，高熵位倾向用于 Bank

课件给出的调度三原则：

  1. 优先行缓冲命中以提高带宽；
  2. 优先延迟敏感的应用以改善系统吞吐；
  3. 保证没有应用长期饥饿，以兼顾公平性。它们可能互相牵制，例如一直优先 Row Hit 会让其他请求等得过久。

课堂可补充：具体调度算法、地址字段位数，以及给定请求序列时怎样排命令。

六、多通道与多处理器：带宽及NUMA
#

课件：第 74—79 页。

增加同一通道上的 DIMM 主要扩充容量，增加独立通道才提供更多独立的数据传输资源。课件比较两种多通道组织：

组织 工作方式 理解重点
Lock-step 多个通道协同，作为更宽的逻辑接口 强调共同服务一次较宽传输
Independent Channels 通道可独立调度请求 强调不同请求的并行处理

多处理器系统可以让每颗 CPU 拥有自己的内存控制器与本地 DRAM，容量和带宽随处理器扩展。访问其他 CPU 连接的内存时，需要经过处理器互连，形成 NUMA（Non-uniform Memory Access，非一致内存访问）：

CPU 0 ─ 本地内存 0
  │ 处理器互连
CPU 1 ─ 本地内存 1

CPU 0 访问内存 0 是本地访问，访问内存 1 是远程访问，后者通常延迟更高、还占用互连资源。因此线程与数据放在哪里，也会影响实际性能。

【79页？】

课件中的插槽颜色、具体互连名称属于平台实例，实际安装规则应以对应机器为准。

七、目标三：提高接口速率与保证信号质量
#

课件：第 80—99 页。

DRAM 阵列内的电容充放电、感应和恢复难以无限加速，所以不能只靠提高阵列核心频率。课件的思路是：内部一次取出更宽的数据，经 I/O 缓冲转换为外部较快的连续传输。

概念 含义
DDR 在时钟的两个边沿传输数据
2n / 4n / 8n Prefetch 每次内部访问为每个外部数据引脚准备多个连续数据单元，分别对应课件中的 DDR、DDR2、DDR3 示例
并转串 内部较宽、较慢的数据通路，经 I/O 接口转换成外部较窄、较快的传输

这里的 Prefetch 是 DRAM 内部接口组织，与上一篇“预测 CPU 未来会访问哪个缓存块”的硬件预取器不同。课件第 87 页关于内外总线宽度的文字方向容易混淆，应结合第 86 页的并转串图理解：内部并行准备的数据更宽，外部依次输出。

频率与数据率也要区分。DDR 每周期传两次，若接口时钟为 \(f\)，理想数据率为 \(2f\) 次传输 / 秒。理论峰值带宽可写为：

$$ \text{带宽}=\text{数据率}\times\frac{\text{数据接口位宽}}{8} $$

例如，64-bit 接口、3200 MT/s 的理论峰值带宽为 25.6 GB/s。实际还存在命令、刷新、行切换与读写切换等开销；更高数据率不代表首次读取延迟同比下降。

高速接口的挑战 课件中的解决方向 直观理解
功耗增加 降低工作电压 在速度、可靠性与功耗之间取舍
Clock Skew，边沿到达时间偏差 Source-synchronous，源同步 DQS 数据发送方同时发送选通信号，帮助接收方确定采样时机
信号反射 Termination，端接 用合适的端接电阻与阻抗匹配减少反射
噪声与时序不确定性 更可预测的互连拓扑 课件对比 DDR2 的 T 分支与 DDR3 的 Fly-by，便于管理或校正传播延迟

课件里的 DDR 代际参数用于说明演进思路；例如 Micron 的 DDR4 UDIMM 规格列出的引脚数为 288，课件第 91 页写成 284，记录时应避免照抄。端接使用的也是电阻（resistor），不是寄存器（register）。

八、复习线索与课堂补充
#

复习时可沿一条请求走：Cache Miss → 控制器队列 → 物理地址映射 → Bank 行状态判断 → PRE / ACT / READ 等命令 → 数据总线返回。把结构、时序和调度连起来，比单独记缩写更容易理解。

43—51、102 第四节：容量扩展与缓冲模块
52—73 第五节：控制器、行策略、Bank 并行、映射与调度

100—101 结束页与访问流程回顾
